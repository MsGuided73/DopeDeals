## Project knowledge — load this before working

### Hard rules from the user
1. **`/brands` is legacy and not functional.** Never link to it. Canonical brand-listing destination is **`/#brands`** (anchor → `<section id="brands">` in `app/components/TrustedBrandsBulletin.tsx`, eager-loaded on the homepage). Per-brand links go to `/search?brand=<name>`. Memory file: `project_brands_route_legacy.md`.
2. **`category_slug` and `subcategory_slug` are how products are categorized**, not a per-product `slug`. Per-product `slug` is a separate URL identifier (used by PDP routing, sitemap, search, article rails) and was just added in migration `20260506_add_slug_to_main_site_products.sql` (backfilled from `name`).
3. **Compliance is non-negotiable** — see CLAUDE.md. Age gate, Kratom block in middleware, THCA restricted states. The `/api/checkout` compliance check is FAIL-CLOSED on errors (returns 503 if it can't verify).
4. **One footer at a time.** Global `Highway420Footer` is rendered in `app/layout.tsx` for every route. **Do not add inline `BlogFooter` / `EssentialsFooter` to individual pages** — that creates dupes (already cleaned up across 7 files).

### Schema quirks (live DB confirmed via MCP queries)
- **No per-product `category` column** on `main_site_products` — has `category_id` and `category_slug` only. Older code that queried `category` is broken (just patched in `app/api/checkout/route.ts`).
- **No `compliance_id` on `product_compliance`** — its FK to compliance rules goes through `categories` (text array) overlapping `compliance_rules.category` (text). Just patched.
- **`coa-url` column has a literal hyphen** — quote in PostgREST/Supabase queries.
- **Brand linkage on products goes through `brand_name`**, not a foreign key (legacy paths).
- `products` is **deprecated** — use `main_site_products` only (CLAUDE.md DATABASE_POLICY).
